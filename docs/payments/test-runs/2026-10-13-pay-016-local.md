# PAY-016 — klient OAuth, 13 października 2026 r.

- Środowisko: lokalny proces API, Tpay Sandbox; wersja: bieżący workspace po PAY-015 z implementacją PAY-016.
- Testy jednostkowe: **PASS, 5/5** (`tpay-api.client.spec.ts`). Cache, wygaśnięcie z marginesem, jedno odświeżenie dla równoległych wywołań, 401 i timeout. Test sprawdza, że błąd i przechwycone logi nie zawierają fikcyjnego sekretu.
- MT-001 przez nowego klienta: **PASS**. Wywołanie `getAccessToken()` uzyskało token z Sandbox; odpowiedź podała `expires_in=7200` sekund. Wykonano dwa żądania OAuth: pierwsze potwierdziło uzyskanie tokenu, drugie odczytało czas ważności. Nie zapisano wartości tokenu, Client ID ani Client Secret.
- Logi procesu testowego: zawierały tylko potwierdzenie wyniku i czas ważności; nie zawierały tokenu ani danych dostępowych. Błędy klienta mają stałe, maskowane komunikaty.
- Baza danych, schemat, transakcje płatnicze i checkout: bez zmian; test nie uruchamiał API ani nie otwierał ekranów. Zachowanie niedostępnego checkoutu pozostaje poza zakresem tego klienta.
- Pozostałe: zapytanie PAY-003 do Tpay pozostaje niewysłane; błąd lokalnego schedulera o brakującej tabeli `agency_plan_checkout_attempts` i dodatkowe kontrole ról/flag PAY-011 nadal pozostają odnotowane osobno.
