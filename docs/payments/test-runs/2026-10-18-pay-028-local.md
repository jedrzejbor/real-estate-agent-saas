# PAY-028 — protokół lokalny

- Data: 18 października 2026 r.; środowisko: lokalny kod i odizolowana baza PostgreSQL `real_estate_saas_pay028_test`. Tester automatyczny: Codex. Publiczny checkout: wyłączony.
- Testy automatyczne: **Pass, 6/6** (`PAY028_DB_INTEGRATION=1 pnpm --filter api test -- --runInBand src/listing-commerce/listing-tpay-fulfillment.integration.spec.ts`). Sprawdzono pełną zapłatę i pojedyncze uprawnienie, niedopłatę i niezgodne ID/merchant/kwotę/walutę, nieznany lokalny Payment ID, powtórzony webhook, dokończenie wcześniej zapisanego lecz niezrealizowanego zdarzenia oraz rollback przy awarii realizacji. Podpis JWS był mockowany tylko w tym teście integracji; kryptograficzne testy PAY-025 pozostają oddzielne. Nie połączono się z Tpay.
- Podczas przygotowania test ujawnił błąd PostgreSQL przy `FOR UPDATE` na ogłoszeniu z opcjonalną relacją `Address`. Blokada w `ListingEntitlementsService` została ograniczona do wiersza ogłoszenia; końcowy przebieg testów przeszedł. Sprawdzono także niezgodność tytułu zapisanego w zamówieniu i próbie płatności.
- Kontrola kompilacji typów: **Pass** (`pnpm --filter api type-check`).
- Zmiany bazodanowe: utworzono dwukrotnie wyłącznie `real_estate_saas_pay028_test` na potrzeby iteracji testów. Każdy przebieg odtwarzał schemat z encji w tej bazie, wstawiał wyłącznie fikcyjne rekordy i usuwał swój schemat. Końcowe odczyty wykazały **0 tabel**, po czym dwukrotnie usunięto pustą bazę testową. Baza robocza `real_estate_saas` nie została migrowana ani zmieniona; odczyt wykazał brak tabel `payments` i `payment_events`. Nie dodano migracji ani nie zmieniono schematu roboczego.
- MT-003 — pełna płatność BLIK i powrót do panelu: **Blocked**. Publiczny checkout nadal zwraca `PAYMENTS_UNAVAILABLE`, wcześniejsza strona płatności Sandbox zwracała HTTP 403, a robocza baza nie ma wymaganych tabel. Nie obchodzono blokady, nie tworzono nowej transakcji Sandbox i nie używano pieniędzy. Test automatyczny nie zastępuje ręcznego MT-003.
- Ręczny replay MT-005: **Blocked** bez bezpiecznej podpisanej notyfikacji i lokalnej płatności w roboczej bazie. Zachowanie duplikatu jest pokryte testem integracyjnym PAY-028.
- Do odbioru po usunięciu blokad: MT-003 i MT-005 na bezpiecznym Sandbox; ponowić MT-006 dla podpisu na właściwym endpointcie. Kontrole ról i flag z PAY-011 pozostają nieodnotowane.
