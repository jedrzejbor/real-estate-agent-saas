# PAY-031 — protokół lokalny

- Data: 20 października 2026 r.; środowisko: lokalny kod i izolowana baza PostgreSQL `real_estate_saas_pay031_test`. Tester automatyczny: Codex. Publiczny checkout: wyłączony.
- Kontrakt operatora: [Tpay Refunds](https://docs-api.tpay.com/en/refunds/) i [Open API](https://api.tpay.com/) opisują `GET /refunds/{refundId}`. Statusy `New`, `Pending`, `Hold`, `Processed` i `BLIK_pending` są stanami oczekiwania; `Done`, `BLIK_processed` i `BLIK_incorrect` oznaczają zrealizowany zwrot według opisu Tpay; `Cancel` oznacza anulowanie. Odczyt bez zgodnego ID, kwoty i waluty nie potwierdza lokalnego zwrotu.
- Testy automatyczne PAY-031: **Pass, 13/13** (`PAY031_DB_INTEGRATION=1 pnpm --filter api test -- --runInBand --runTestsByPath src/payments/infrastructure/typeorm/refund.integration.spec.ts src/payments/infrastructure/tpay/tpay-api.client.spec.ts -t PAY-031`). Sprawdzono rollback migracji, unikat intencji w PostgreSQL, częściowe zwroty i limit sumy, blokadę po `unknown` przez nową instancję serwisu, dwóch równoległych nadawców, zgodny/niezgodny odczyt operatora, rollback lokalnego zapisu oraz mapowanie statusów GET. Provider HTTP był mockowany; nie wysłano żądania do Tpay.
- Kontrola typów API: **Pass** (`pnpm --filter api type-check`).
- Zmiany bazodanowe: dwukrotnie utworzono tylko `real_estate_saas_pay031_test`. Testy zakładały fikcyjne tabele zależne, uruchamiały istniejącą migrację `payments` i nową `20261020_refunds.sql`, wstawiały fikcyjne płatności i zwroty, po czym usuwały wszystkie tabele. Po końcowym przebiegu kontrola wykazała **0 tabel**; pusta baza testowa została usunięta. Bazy roboczej nie migrowano ani nie zmieniano.
- MT-015 i kontrola historii zamówienia: **Blocked**. Jedyna znana transakcja Sandbox `TR-58WE-KV1S3X` była oczekująca, nie opłacona. Publiczny checkout pozostaje wyłączony, strona płatności wcześniej zwróciła HTTP 403, a w UI nie ma akcji ani historii zwrotów. Nie tworzono płatności i nie używano realnych środków.
- Ograniczenia: `requesting` lub `unknown` bez identyfikatora zwrotu operatora wymaga ręcznego uzgodnienia, bo `GET /refunds/{refundId}` nie może go odnaleźć. PAY-031 nie nadaje roli do zwrotu, nie udostępnia akcji UI, nie zmienia statusu zamówienia, płatności ani uprawnienia i nie rozstrzyga polityki zwrotów. Kontrole ról i flag PAY-011 oraz MT-004/005/006 nadal są nieodnotowane lub Blocked.

Manual regression required: MT-015.
